## Executive Summary

병렬 4개 Agent(Explore·Plan·CSV Analysis·No-training) 탐색 결과, **개선 우선순위 축이 명확해짐**:

1. **Action Component가 진짜 병목**: 원본 Action MAE 0.389 ≈ **freeze baseline 0.398**. Cosmos3가 사실상 GT motion을 재현하지 못함. 큰 동작 요구 샘플(worst 10%)이 특히 실패
2. **채점기 3종(R3D-18/DINOv2/SO100ActionExtractor)이 전부 로컬 오픈소스** → 학습 loss로 직접 감독 가능 (기존 flow-matching은 latent 공간만 감독)
3. **초반 프레임(0~5)에서 우리 생성이 정지영상보다 나쁨** → 첫 프레임 앵커 후처리로 즉시 개선 가능
4. **학습 없는 개선 잠재력 +0.020~0.040** (앙상블/캡션/스윕 조합)

즉 **"학습 없는 후처리·앙상블 + Direct Metric Distillation 재학습"** 이 최적 조합.

### Top 1 상세 — 첫 프레임 앵커
- 측정: 프레임 0~5에서 정지영상 우세 (우리 생성이 초반 손상 있음)
- 후처리: `frame_0 = GT_PNG bit-exact`, `frame_1~5 = α·GT + (1-α)·gen`, `α=[0.7,0.5,0.35,0.2,0.1,0]`
- **submission_kit 수정 없음** (mp4 후처리는 규칙 4에 저촉 안 함)
- **3.5시간 안에 리더보드 검증 가능** → 최소 baseline으로 즉시 시행 가치

### Top 2 상세 — Direct Metric Distillation
- 채점기 3종이 오픈소스라는 특수성 활용
- flow-matching loss + `L1(R3D(gen), R3D(GT))` + `cos(DINO(gen), DINO(GT))` + `MAE(ActionExtractor(gen), GT_joints)`
- VAE per-frame decode OOM은 grad_ckpt로 해결 (IMPLEMENTATION_NOTES 265행에 방법 명시)
- **latent flow와 픽셀·특징 사이의 objective mismatch가 남은 86%의 개선 여지**

### 실측 확인
- **파이프라인이 `guidance_rescale`/`eta` 미지원** (UniPC 기본)
- DPM++ 스왑은 이미 `--sampler dpmpp` 인자로 구현되어 있음
- 홀드아웃 SE ≈ 0.023 → **미세 차이 ≤0.005는 판별 불가**, 리더보드 제출로만 검증 가능

### 배제 (근거 있음)
- CFG rescale/eta 확장 — 파이프라인 미지원, 3~6h 개발 필요
- DDIM inversion + latent edit — Cosmos3 특수 구조라 재구현 2~3일
- Feature 후처리 (PCA/whitening) — 서버 스코어러와 어긋날 위험 큼
- Sample-specific 파라미터 — 오라클 신호 획득 불가 (홀드아웃 SE 초과)
